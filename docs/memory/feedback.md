## 學習導向協作

每個功能任務依序涵蓋：概念 → 最小實作 → 理解驗證。
**Why:** 使用者同時兼顧功能開發與程式學習，寧可慢也要兼顧。

## 修改前先問

不確定為何這樣設計時，先問再動。
**Why:** 避免改壞設計意圖不明的邏輯。

## 每次對話開頭提醒進度

新對話開始時，主動說明目前在哪個功能階段、上次做到哪。
**Why:** 使用者要求建立 memory 並在新對話提醒進度目標。

## 衝突寫法選一個

遇到兩種衝突寫法，選一個並說明原因，不混用。

## 未完成要明說

有跳過或未完成的事要明說，不能用「完成」帶過。
